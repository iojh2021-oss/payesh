# پایش (Payesh)

رصد ترافیک اینترنت همهٔ برنامه‌های اندروید (سیستمی و غیرسیستمی) بدون نیاز به روت.

## امکانات
- نمایش مقصد (دامنه/آی‌پی)، پورت، پروتکل (TCP/UDP) و حجم ارسال/دریافت روبروی آیکون و نام هر برنامه
- تشخیص برنامه‌های **فعال**، **پیش‌زمینه / پس‌زمینه** و **در حال دانلود** (با سرعت)
- نمایش برنامه‌هایی که ترافیکی ندارند («بدون ترافیک»)
- فیلتر (فعال، دانلود، سیستمی، غیرسیستمی) و جستجو
- آدرس کامل (URL) برای ترافیک HTTP ساده؛ برای HTTPS فقط دامنه (SNI) دیده می‌شود

## روش کار
یک VPN محلی (`VpnService`) روی خود گوشی ساخته می‌شود. همهٔ بسته‌های IPv4 برنامه‌ها از آن می‌گذرند،
با `ConnectivityManager.getConnectionOwnerUid` به برنامهٔ صاحب اتصال نسبت داده می‌شوند و سپس با سوکت‌های محافظت‌شده
به اینترنت واقعی فرستاده می‌شوند. به‌طور پیش‌فرض هیچ داده‌ای به سرور دیگری ارسال نمی‌شود. فقط اگر خودت «ارسال گزارش به داشبورد» را روشن کنی، خلاصهٔ وضعیت (شمارنده‌ها، نتیجهٔ اسکن، رویدادها) به سرور خودت فرستاده می‌شود؛ نه محتوای فایل‌ها و نه ترافیک.

## ساخت APK
گیت‌هاب اکشنز (`.github/workflows/build.yml`) با هر push روی `main` فایل APK می‌سازد:
Actions ← آخرین اجرا ← Artifacts ← `payesh-debug-apk`.

## پوش با Termux
```sh
pkg install git unzip
termux-setup-storage
cd ~ && unzip ~/storage/downloads/payesh.zip && cd payesh
git init && git branch -M main
git add . && git commit -m "Initial commit"
git remote add origin https://github.com/iojh2021-oss/payesh.git
git push -u origin main
```
(برای رمز، از Personal Access Token گیت‌هاب استفاده کن.)

## محدودیت‌ها
- فقط IPv4 رصد می‌شود (IPv6 از مسیر VPN عبور نمی‌کند)
- با روشن بودن VPN دیگر، اندروید فقط یک VPN را فعال نگه می‌دارد
- محتوای HTTPS خوانده نمی‌شود، فقط دامنه و پورت
- تشخیص پیش‌زمینه نیاز به دسترسی Usage access دارد

## موتور Rust و محافظ لحظه‌ای
هستهٔ تحلیل (SHA-256، اسکنر چندالگویی Aho-Corasick، آنتروپی)، پایشگر لحظه‌ای فایل‌ها (inotify) و بررسی نشانه‌های دستکاری سیستم
در `app/src/main/rust` با Rust نوشته شده و در گیت‌هاب اکشنز با `cargo-ndk` ساخته می‌شود. اگر کتابخانه بارگذاری نشود، برنامه
به پیاده‌سازی Kotlin برمی‌گردد.

**محدودیت مهم:** برنامهٔ بدون روت نمی‌تواند داخل کرنل را ببیند. روت‌کیت سطح کرنل می‌تواند از هر بررسی سطح برنامه پنهان شود.
بخش «سلامت سیستم» فقط نشانه‌های قابل‌مشاهده را گزارش می‌کند (su، Magisk، بوت‌لودر باز، SELinux Permissive، Verified Boot، کتابخانه‌های هوک).

## پایگاه تهدید و بررسی دوره‌ای
- `av-db/build_db.py` علاوه بر MalwareBazaar و stalkerware-indicators، از **ThreatFox** هم می‌خواند (نیازمند `ABUSECH_AUTH_KEY` در Secrets): دامنه‌های C2/توزیع بدافزار اندروید (`apk.*`)، دامنه‌های C2 با اطمینان بالا و هش APKها. API فقط ۷ روز اخیر را می‌دهد، پس دامنه‌های قدیمی ThreatFox در خروجی نگه داشته می‌شوند (سقف ۲۰هزار دامنه).
- در بیلد APK، آخرین `av-db.json` منتشرشده از شاخهٔ `av-db` داخل `assets` گذاشته می‌شود تا اولین اجرای آفلاین هم پایگاه کامل داشته باشد (اگر نشد، همان نسخهٔ قبلی می‌ماند).
- `GuardService` علاوه بر لحظهٔ نصب، برنامه‌های نصب‌شده را هم دوره‌ای بررسی می‌کند: برنامه‌های جدید/به‌روزشده، و همهٔ برنامه‌های غیرسیستمی هر وقت نسخهٔ پایگاه عوض شود. برنامهٔ خطرناک اعلان جدا می‌گیرد؛ موارد مشکوک در یک اعلان خلاصه می‌آیند.

## بازرس شبکه (تحلیل عمیق IP و پورت)
در صفحهٔ آنتی‌ویروس یک کلید روشن/خاموش دارد. وقتی روشن است و VPN پایش فعال است، `PayeshVpnService` اولین بایت‌های هر اتصال
(حداکثر ۱۵۰۰ بایت، دو بستهٔ اول هر جهت) را فقط در حافظه به `NetScan` می‌دهد. از روی آن‌ها نوع پروتکل و رمزنگاری تشخیص داده می‌شود:
نسخهٔ TLS، ALPN، رمز انتخاب‌شده، ECH، QUIC، SSH، DNS، DTLS، WireGuard، OpenVPN، HTTP و … ؛ بعد با پایگاه دامنه‌های مخرب،
پورت‌های پرخطر، رمزهای منسوخ، کانال‌های پرآنتروپی روی پورت غیراستاندارد و ارسال حجیم در پس‌زمینه تطبیق داده می‌شود.
محتوای ترافیک رمزنگاری‌شده خوانده نمی‌شود و چیزی ذخیره یا ارسال نمی‌شود. اسکن فعال سرورهای دیگر (port scan) انجام نمی‌شود.
اتصال‌هایی که قبل از روشن‌شدن کلید برقرار شده‌اند فقط از روی پورت حدس زده می‌شوند. فقط IPv4 از VPN عبور می‌کند.

## DNS رمزنگاری‌شده (DoT)
در صفحهٔ آنتی‌ویروس یک کلید دارد. برنامه‌ها همچنان از 1.1.1.1 / 8.8.8.8 (آدرس‌هایی که VPN پایش می‌دهد) می‌پرسند، ولی وقتی کلید روشن است،
`PayeshVpnService` همهٔ پرسش‌های UDP/53 را می‌گیرد و `DnsProxy` آن‌ها را با DNS-over-TLS (پورت 853، با راستی‌آزمایی گواهی و نام سرور)
به سرویس انتخابی (Quad9، Cloudflare، Google، AdGuard یا سرور خودت) می‌فرستد و پاسخ را به تونل برمی‌گرداند. اگر اتصال امن جواب ندهد
و گزینهٔ بازگشت روشن باشد، همان پرسش به DNS ساده می‌رود و بعد از سه شکست پشت‌سرهم یک دقیقه از DoT صرف‌نظر می‌شود.
سرویس انتخابی نام سایت‌ها را می‌بیند. نام‌های شبکهٔ محلی (مثلاً روتر) از این مسیر حل نمی‌شوند.

## رمزنگاری پسا‌کوانتومی (TLS)
همهٔ اتصال‌های HTTPS خود برنامه و کانال DNS امن با `Pq.factory` ساخته می‌شوند: کتابخانهٔ Conscrypt 2.7.0 (BoringSSL) که همراه برنامه است،
نه کتابخانهٔ داخل گوشی. این نسخه تبادل کلید ترکیبی X25519MLKEM768 (کلاسیک + ML-KEM-768، استاندارد FIPS 203) را پیش‌فرض پیشنهاد می‌دهد.
اگر سرور هم پشتیبانی کند، کلید جلسه در برابر «ضبط الان و رمزگشایی بعداً» محافظت می‌شود. گواهی سرور هنوز کلاسیک است (CAهای عمومی گواهی PQ نمی‌دهند).
دکمهٔ «تست پیشنهاد PQ» در صفحهٔ آنتی‌ویروس، ClientHello واقعی را روی لوپ‌بک می‌خواند و نشان می‌دهد برنامه چه گروه‌هایی را پیشنهاد می‌دهد.
اگر کتابخانهٔ همراه بارگذاری نشود، TLS سیستم استفاده می‌شود. حجم APK چند مگابایت بیشتر می‌شود.

### DoT و DoH
دو مسیر امن دارد: DoT (TLS روی پورت 853؛ بعضی شبکه‌ها می‌بندند) و DoH (HTTPS روی پورت 443؛ شبیه ترافیک عادی وب). حالت «خودکار» اول مسیری را که آخرین بار جواب داده امتحان
می‌کند و بعد دیگری را؛ هر مسیری که دو بار پشت‌سرهم شکست بخورد ۳ دقیقه کنار گذاشته می‌شود. «تست DNS امن» هر دو مسیر را جدا امتحان می‌کند و دلیل شکست
(مرحلهٔ اتصال TCP، دست‌دهی TLS یا پاسخ HTTP) را نشان می‌دهد.

### صداقت گزارش و لاگ DNS
بازرس شبکه فقط وقتی DNS را «رمزنگاری‌شده» می‌نویسد که در پنج دقیقهٔ اخیر پاسخ امن واقعی رسیده باشد؛ وگرنه «بدون رمزنگاری» و دلیل آخرین خطا را نشان می‌دهد.
هر دقیقه حداکثر یک خط `dns:` در لاگ می‌آید (مرحلهٔ شکست: اتصال TCP یا دست‌دهی TLS یا پاسخ HTTP). هنگام توقف محافظ هم `guard stopped` ثبت می‌شود.

## ممیزی پسا‌کوانتومی ترافیک (بازرس شبکه)
بازرس شبکه حالا نه‌فقط پیشنهاد برنامه، بلکه گروه تبادل کلیدی را که **سرور** انتخاب کرده (key_share در ServerHello تی‌ال‌اس ۱٫۳) می‌خواند و برای هر اتصال TLS می‌گوید:
PQ برقرار شد (مثلاً X25519MLKEM768) / برنامه PQ پیشنهاد داد ولی سرور نپذیرفت / برنامه اصلاً PQ پیشنهاد نداد. خلاصه، درصد اتصال‌های محافظت‌شده،
فهرست برنامه‌ها و مرورگرهای بدون PQ و فهرست سرورهای بدون PQ در کارت و در «کپی گزارش کامل» می‌آید. QUIC (HTTP/3) دست‌دهی‌اش رمز است و از بیرون قابل ممیزی نیست؛
جدا شمرده می‌شود. چیزی رمزگشایی نمی‌شود و فقط متادیتای دست‌دهی خوانده می‌شود.

## رمزنگاری رازهای ذخیره‌شده
توکن داشبورد و کلید VirusTotal با AES-256-GCM و کلیدی داخل Android Keystore (غیرقابل خروج؛ سخت‌افزاری روی گوشی‌هایی که دارند) ذخیره می‌شوند (`Secrets.kt`).
نام تنظیم به‌عنوان داده‌ٔ احرازشده در GCM می‌آید تا مقدار به تنظیم دیگر منتقل نشود. مقدارهای قدیمیِ متن‌ساده هنگام اولین خواندن خودکار رمز می‌شوند.
برای داده‌ٔ ذخیره‌شده روی خود گوشی، کلید متقارن ۲۵۶ بیتی انتخاب درست است و الگوریتم کلیدعمومی پسا‌کوانتومی لازم ندارد.

## نصب روی نسخهٔ قبلی (امضای ثابت)
بدون کلید ثابت، هر بیلد گیت‌هاب با یک کلید debug تصادفی امضا می‌شود و اندروید اجازهٔ نصب روی نسخهٔ قبلی را نمی‌دهد (خطای «در تضاد با بستهٔ موجود»).
یک بار در Termux اجرا کن: `pkg install openjdk-17 gh` و بعد `sh tools/make-keystore.sh`. این کلید را می‌سازد و در Secrets (`KEYSTORE_BASE64` و `KEYSTORE_PASSWORD`) می‌گذارد.
از آن به بعد هر بیلد با همان کلید امضا می‌شود، شمارهٔ نسخه (`versionCode`) با شمارهٔ اجرای گیت‌هاب بالا می‌رود و APK جدید روی قبلی نصب می‌شود.
دو فایل `~/payesh.keystore` و `~/payesh.keystore.password` را جای امن نگه دار؛ اگر گم شوند باید دوباره یک بار برنامه را پاک کنی.
نسخهٔ فعلی که با کلید تصادفی نصب شده باید فقط همین یک بار پاک شود (تنظیمات و قفل برنامه از بین می‌رود).

## امضای ترکیبی پسا‌کوانتومی پایگاه تهدید (ECDSA + ML-DSA-65)
مانیفست پایگاه تهدید دو امضا دارد: ECDSA P-256 (کلاسیک، `manifest.sig`) و ML-DSA-65 (استاندارد FIPS 204، `manifest.sig.mldsa`). وقتی کلید عمومی ML-DSA
داخل APK باشد (`assets/av-pub-mldsa65.pem`) اپ فقط پایگاهی را می‌پذیرد که **هر دو** امضا معتبر باشند؛ شکستن یکی از دو الگوریتم برای فرستادن پایگاه جعلی کافی نیست.
تأیید با Bouncy Castle (از راه reflection؛ نبودن کتابخانه اپ را خراب نمی‌کند) و امضا با OpenSSL 3.5+ در workflow انجام می‌شود (اگر OpenSSL رانر قدیمی بود، داخل کانتینر Alpine).

راه‌اندازی مرحله‌ای (برای اینکه قبل از اجبار، کارکردن تأیید روی خود گوشی دیده شود):
1. در Termux: `pkg upgrade openssl-tool` و بعد `bash av-db/tools/setup_pq_signing.sh` ← کلید خصوصی فقط در Secret `AV_MLDSA_KEY`، کلید عمومی در `av-db/pq/av-pub-mldsa65.pem`. سپس commit و push.
2. در گیت‌هاب workflow «Update AV database» را یک بار اجرا کن؛ فایل `manifest.sig.mldsa` در شاخهٔ `av-db` ساخته می‌شود.
3. در اپ، کارت «رمزنگاری پسا‌کوانتومی» ← «تست امضای ML-DSA دیتابیس». باید «✓ معتبر» ببینی.
4. فقط بعد از دیدن ✓: `sh av-db/tools/enable_pq_enforcement.sh` و commit/push. از آن به بعد اجبار فعال است.
